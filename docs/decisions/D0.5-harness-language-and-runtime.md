# D0.5: Harness language and runtime
Status: Decided | Date: 2026-10-13

## Context
The harness is the foureyes code itself: the benchmark runner, gates, triage, the fix loop, the evidence report and the agent adapters. Its language decides the CI setup, the package name and install path, and who can contribute. The benchmark tasks are TypeScript (D0.4).

The harness drives agent CLIs as separate processes. Codex (`@openai/codex`), OpenCode (`opencode-ai`) and Claude Code (`@anthropic-ai/claude-code`) are all published on npm. Claude Code and Stryker both require Node 22 or later.

## Options considered
| Option | Pros | Cons |
|---|---|---|
| **TypeScript on Node.js** | One toolchain with the benchmark tasks. Installs the same way as the agent CLIs. The largest contributor pool for agent tooling. foureyes can eventually run on its own repo
| TypeScript on Bun or Deno | Faster startup. Built-in TypeScript. Can compile to a single binary | Stryker, Vitest and the agent CLIs target Node; compatibility gaps would cost time |
| Go | Ships as a single binary with no runtime | A second language for contributors. No dogfooding |
| C#/.NET | The maintainer's strongest language | A second toolchain alongside the TypeScript tasks. A smaller contributor pool for agent tooling |

## Decision
The harness is written in **TypeScript and runs on Node.js**.

Toolchain, with versions checked on the npm registry and the Node.js release schedule on 2026-10-13:

| Setting | Choice | Why |
|---|---|---|
| Node.js | `engines: ">=24"`. Develop on Node 24; CI tests Node 24 and 26 | Node 24 is the current Active LTS. Node 26 is scheduled to enter Active LTS on 2026-10-28. Once it does, switch development to Node 26 |
| Module format | ESM only | Current Node and Vitest default; no dual builds |
| TypeScript | 6.0.x, pinned exactly, with `strict` on | typescript-eslint 8.71.2 supports TypeScript below 6.1.0, so TypeScript 7.0.2 (latest) would break type-aware linting. Whether Stryker's TypeScript checker works with 7 is unverified |
| Package manager | npm, with a committed `package-lock.json` | Ships with Node, so contributors install nothing extra |
| Tests | Vitest 5 | Has a maintained Stryker runner (`@stryker-mutator/vitest-runner` 10.0.0) |
| Lint | ESLint 10 with typescript-eslint, using its type-checked rules | Type-aware rules catch unhandled promises, which matters for code that spawns and waits on agent processes |
| Format | Prettier | The most familiar formatter for contributors |
| Packaging | A single npm package named `foureyes` that provides the `foureyes` CLI. No workspaces until a second package is genuinely needed | One install path: `npm install -g foureyes` or `npx foureyes` |

## Consequences: what this commits us to and what it rules out
- The repo scaffold (T0.1) sets up CI on GitHub Actions running lint, type-check and tests on Node 24 and 26, plus a Node `.gitignore`.
- Every harness dependency must be ESM-compatible and carry a license compatible with Apache-2.0 (D0.3).
- The harness calls agent CLIs as child processes and never imports them as libraries. Each agent stays behind its adapter (D3.1).
- The `foureyes` name on npm is unregistered as of 2026-10-13.
- Rules out Bun, Deno, and a single-binary distribution in v1.

## Revisit if
- typescript-eslint and Stryker both support TypeScript 7. Then upgrade to the faster 7.x compiler.
- Node 26 enters Active LTS as scheduled. Then switch development to it and drop 24 from CI after its maintenance window ends (2028-04-30).
- A single-binary install becomes the main thing blocking adoption.
