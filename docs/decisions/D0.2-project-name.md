# D0.2: Project name
Status: Decided | Date: 2026-10-13

## Context
The name goes into the README, the package name, the CLI command and every launch post. "foureyes" was already the working name, and the GitHub repository ArchetaAI/foureyes was created under it.

## Options considered
| Option | Notes |
|---|---|
| **foureyes** | **Chosen.** Already in use as the working name and repository. It references the four-eyes principle: no change is approved by the party that made it. That is the core of the project: the agent never grades itself, and a different vendor's model reviews its work. |
| Rename before the repo scaffold | No alternative was put forward. Renaming is cheapest now and gets costlier after launch. |

No other names were formally evaluated.

## Decision
The project is named **foureyes**, hosted at github.com/ArchetaAI/foureyes.

Availability checked on 2026-10-13:
- GitHub: ArchetaAI/foureyes is held by us.
- npm: `foureyes`, `four-eyes` and `@archetaai/foureyes` all returned 404 (unregistered).
- Domain: not checked.

## Consequences: what this commits us to and what it rules out
- The README, license notice, package name and CLI command use "foureyes".
- The final package and CLI name is confirmed when the harness language and runtime are chosen (D0.5). `foureyes` is the default if it is still available.
- Launch messaging can use the four-eyes principle as the one-line explanation of the name.

## Revisit if
- The npm name is taken before we reserve it, or a trademark conflict turns up.
