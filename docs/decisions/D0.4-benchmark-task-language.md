# D0.4: First language for benchmark tasks
Status: Decided | Date: 2026-10-13

## Context
The benchmark is how every later change is judged, and its 15 original tasks must all be written in one language first. That language decides which mutation-testing tools are available (D1.6), what the task repos look like (D1.1, D1.2), and which audience the first results table speaks to. It also sets the "first target" line in the README.

The language of the harness itself is a separate decision (D0.5). Gates are plain scripts with exit codes, so the harness language doesn't limit what languages users can run foureyes on. The language that needs committing to here is the benchmark's.

## Options considered
| Option | Pros | Cons |
|---|---|---|
| **TypeScript** | Largest audience for agent tooling. Same toolchain as the harness (D0.5). Stryker (`@stryker-mutator/core` 10.0.0, released Aug 2026) and Vitest (5.0.4) are actively maintained |
| Python | The most common language in existing agent benchmarks. mutmut (3.8.0) and cosmic-ray (8.7.0) are maintained | Results get compared head-to-head with existing benchmarks. Higher risk of training-data overlap. A second toolchain in CI |
| C#/.NET | The maintainer's strongest language, so reviews are strongest. Stryker.NET is maintained. Few agent benchmarks cover .NET | Smaller audience on the launch channels. Fewer contributors. Users need the .NET SDK |

Versions were checked on the npm and PyPI registries on 2026-10-13.

## Decision
The first benchmark language is **TypeScript**, running on Node.js.

**First target**, as stated in the README: TypeScript repos, for both repairing existing code and building from a spec.

- The 15 tasks are split 7 repair and 8 greenfield. The task specs (D1.2) settle what each one is.
- Each task repo pins its own Node and TypeScript versions and its own test runner. The task format (D1.1) defines where those pins live. Task repos are independent of the harness toolchain.
- Stryker is the lead candidate for mutation testing. The mutation-testing decision (D1.6) settles the tool and the score threshold.

## Consequences: what this commits us to and what it rules out
- The repair and greenfield tasks (T1.2, T1.3), the hidden tests (T1.4) and the mutation step (T1.7) are all TypeScript.
- Public results describe lift on TypeScript tasks only. Nothing we claim (D4.1) can generalise the results to other languages.
- The quickstart and example repo are TypeScript.
- Rules out multi-language results in v1. A second task language (C# is the lead candidate) comes back as its own decision after launch.

## Revisit if
- Stryker can't run reliably inside the benchmark isolation setup (D1.3), and no other TypeScript mutation tool can.
- Baseline runs show plain agents scoring near the ceiling on TypeScript tasks, so the tasks can't show lift. Harder tasks are the first fix; a different language is the second.
- Early users mostly ask for a different language.
