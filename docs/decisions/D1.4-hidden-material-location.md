# D1.4: Where hidden tests, held-out tasks and reference solutions live
Status: Decided | Date: 2026-10-14

## Context
The benchmark's credibility depends on three kinds of material that agents under test must never see and future models should not train on:
- hidden tests
- the 5 held-out tasks
- reference solutions

The promise also depends on them, because the agent never grades itself. Launch (Phase 4) also promises results that outsiders can reproduce. This decision sets where that material lives and when, if ever, it becomes public. It unblocks T1.1, T1.2, T1.3, T1.4 and T1.6.

## Options considered
- **A. All private.** A private repo holds everything, and the public repo publishes only hashes. The strongest secrecy, but hidden-test scores can never be reproduced outside.
- **B. Encrypted in the public repo** (git-crypt, age or sops). Rejected: git-crypt decrypts into the working tree, so agents working in an unlocked checkout would read plaintext hidden tests. A leaked key cannot be undone.
- **C. Split, reveal at launch.** Private until launch. At launch, publish the hidden tests and reference solutions for the 10 tuning tasks, and keep the 5 held-out tasks private permanently.
- **D. All public, rotated per release.** Rejected: contamination is guaranteed once the material is crawled, and writing 15 new tasks per release is not sustainable for one maintainer.

## Decision
**Option C.**
- All hidden material lives in the private repo `ArchetaAI/foureyes-bench-private` until launch.
- The public repo `ArchetaAI/foureyes` contains a manifest with the SHA-256 of every hidden file. D1.1 owns the manifest's format and location.
- At launch, the hidden tests and reference solutions for the 10 tuning tasks are published, and they must verify against the hashes committed before launch.
- The 5 held-out tasks are never published. Their prompts, starting repos, hidden tests and reference solutions all stay private, with only their hashes public.
- The ArchetaAI org is on GitHub Team, so rulesets are enforced on the private repo.

## Consequences: what this commits us to and what it rules out
- **Two repos.** The private repo has its own AGENTS.md. It permits committing hidden tests and reference solutions there, and forbids copying anything from it into the public repo. The public AGENTS.md rule "never commit hidden tests or reference solutions" stays unchanged and applies to the public repo.
- **Protection parity.** The private repo carries rulesets equivalent to the public `protect-main`. Forking of private repos is disabled at org level.
- **Byte-identical hashing.** The private repo uses the same `.gitattributes` (`* text=auto eol=lf`) as the public repo, so hashes match on every OS and in CI.
- **No nesting.** The private repo is cloned as a sibling of the public repo, never inside it or inside any agent workspace.
- **Vendor training is opted out.** Before any agent reads or writes hidden material, model-training opt-outs are confirmed off on every account used for T1.2–T1.5. That covers Anthropic, ChatGPT data controls and Codex's separate full-environment setting. Record the date of each check. Opt-outs apply to future data only.
- **Accepted limit.** Held-out task prompts and starting repos reach model vendors on every benchmark run. Opt-outs reduce the risk but cannot remove it.
- **Held-out runs stay private.** Raw logs from held-out runs are not published, because failing-test output can reveal hidden tests. Only aggregate held-out results are published.
- **Contamination after launch.** After launch, the 10 revealed tasks will drift towards contamination. Re-run day (D5.2) leads with held-out results and labels tuning-set results as possibly contaminated.
- **Community tasks.** Community-submitted tasks (Phase 5) will need a private way to submit hidden tests. That is for D5.1.
- **Rules out:** hidden material in the public repo in any form, including encrypted, before launch. It also rules out ever publishing held-out material.

## Revisit if
- Training opt-outs cannot be confirmed on an account used for hidden-material work.
- Hidden material leaks, or a manifest hash fails to verify.
- The GitHub Team plan lapses, which would leave the private repo's rulesets unenforced.
- Re-run day shows held-out lift diverging sharply from tuning lift.
- D5.1 needs a different home for community hidden tests.
